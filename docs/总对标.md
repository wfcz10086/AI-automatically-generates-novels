# 从两本书里学到什么：全系统对标

读的是大罗罗《大宋有种》（555 章 217 万字）与《抢救大明朝》（2278 章 575 万字），
共 2833 章、796 万字。同一个作者两本，才能把**框架**和**种子**切开。

所有结论都跑过实测（`scripts/prompt_bench.py` / `draft_ab.py` / `reverse_outline.py`），
**包括推翻我自己的两条**。

---

## 一、七条启示

### 1. 情节不是想出来的，是**结算**出来的

前三十章的三个动作是：**闯个门、说句话、睡一觉**。没有一个是"精彩情节"。
但三轮下来六本账翻了三倍，还长出「卖国」「疯王」「黄袍加身」三条能烧几十章的长线。

因为作者做的不是"设计冲突"，是**老实推演每个人会怎么误会这个动作**。

> 赵楷在陈桥驿睡了一觉（真实意图：他太困了）
> → 宰执凭「这是太祖黄袍加身处」读成"他要称帝" → 集体闭嘴 → **朝廷失去全部约束力**
> → 部下凭同一条典故读成"该劝进了" → 真去找黄袍 → 主角被吼醒，被迫表态并顺势整编军队

对提示词的含义：**别问「请设计一个精彩的冲突」，问「李邦彦现在最怕什么？他看见这一幕会怎么想？」**
前者让模型去检索"精彩冲突"的模板，收敛到训练数据的众数；后者逼它推理，推理才有意外。

### 2. 金手指必须是**一套看世界的方法**，不能是一种力量

《大宋有种》是兵法，《抢救大明朝》是特许金融分析师（第 1 章就拿毛笔画 SWOT 表分析"大明这家公司"）。

方法能持续产出新解法；力量只能产出一次爽点。
现有项目写的「一把沙漠之鹰、一百二十发子弹」是后者 —— 它有上限，打完就没了，撑不起三百章。

而且**金手指的盲区决定了整条但是链**：DeepSeek 实测生成的种子里，金手指是"庙堂剧场术"，
盲区写的是「只对相信符号的人有效……白沟河的风一落地，庙堂剧场术瞬间变废纸」—— 盲区直接咬住时钟。

### 3. 大事件是**一个事件 × N 个视角**，不是 N 个事件

《抢救大明朝》第 852–876 章，**连续 25 章全叫《什么？大清没了！》**，约 6.3 万字，
写的是同一场战役，视角依次是史可法 → 多铎 → 明军火枪连 → 清军巴图鲁詹岱 → 索尼 → 孝庄 → 鳌拜。
**大半是输家的眼睛。**

现有框架是「346 章 = 346 个不同事件」。一章一个新事件 → 事件编不出来就注水 →
状态每章被推一下 → 漂移。

### 4. 目录是一部**对手受难史**

2833 个标题里，点对手名字的次数是点主角的 **1.6~2.8 倍**。
被点最多的前十位里只有第三名是主角：黄台吉 21、吴三桂 16、赵楷 13、崇祯 12、李自成 10。

判据：**念出这个标题，能不能听出是谁在开口？** 听不出就是废标题。
对照现在生成的「第1章 头七夜的第一声雷」「第2章 说不通的洞」—— 目录页上一片死寂。

### 5. 支线是**一群手里攥着牌的人**，不是一张待办清单

逐章扫描人名分布，是「大簇 + 长空白」：
秦桧最大空白 183 章，洪承畴 **781 章**，王承恩 **1047 章**；一回来就是连续 8~72 章的密集簇。

`threads.json` 的 `cadence: 12`（每 12 章推一次）是节拍器，与真实形状完全相反。

真机制：每个人手里有一张牌（把柄／债／身份／手艺／队伍），牌价随局势浮动。
**牌一变值钱，他自己就冒出来。** 作者不需要记得支线，每回合只需重估一次牌价。

推论：现有的「断线角色必须回归」是**错误约束** —— 它强迫手上没牌的人回来刷存在感。

### 6. 提示词里写什么，模型就做什么；**没写的会被挤掉**

A/B 实测最干净的一条证据：
把数值目标换成结构指令后，误读 0→2.7、反讽 0.3→5.3、解说 0.7→3.3；
但**唯独没给「情绪外放」写指令，叹号密度从 8.20 塌到 0.14**（原作 8.90）。
补一条「情绪要喊出来」，立刻回到 7.72。

而且**只给下界必超调**：「至少四次」让反讽冲到 6.7，原作只有 2.0。

### 7. 我自己错了两条，都是被真数据打掉的

**错一**：我说「反讽旁白密度 22.4/22.1 每万字，两本几乎完全一致，这是作者的嗓子」。
错。那个数由「不是」（8307 次）这类普通词撑起来。分强弱重测后 ——
**招牌起手（还别说／说穿了／可问题是）原作每章只有 0.12~0.24 次，基本不用。**
戳破靠句子本身的转折，不靠固定起手。我按错误结论写的提示词，让模型用了 6.7 次，是原作的 30 倍。

**错二**：我以为这是短句快节奏。错。
原作句均 **23~30 字**、句长 80 分位 **40~49 字**。
提示词里写「段落短」，把句子切到了 15.9 字，读起来就不是这个味了。

> **教训：所有"文风"判断都必须过一遍真数据。凭感觉写出来的规格会把模型带偏，而且带得很远。**

## 二、逐层对标

### 层 1 · 种子与发散

| | 现在 | 原作 | 实测 | 该怎么改 |
|---|---|---|---|---|
| 输入字段 | `premise / background / relationships`（人设+金手指+三条感情线） | 时钟 / 壳 / 反直觉动作 / 方法+盲区 / 预装情绪 / 六本账 / 但是链 / 自造误读 | 两个模型都从新字段产出了过「他疯了？」检验的动作 | 换成八项。八项不是设定，是发动机的八个进油口 |
| 发散方式 | 一次性排完 346 章细纲 | 递归：这一轮的输出是下一轮的输入 | 12 步链路跑通 | 回合推演：自转→碰撞→常规解→反直觉→误读扩散→牌市重估 |
| 发散算子 | 无 | 误读(一变多)／代价(一变二)／自转(横向)／作废(纵向)／换壳(重启) | — | 五个算子写进流程 |

### 层 2 · 总纲与卷纲

| | 现在 | 原作 | 该怎么改 |
|---|---|---|---|
| 卷的定义 | 事件列表（「进入东京权力体系，与蔡京集团博弈」） | 「解决了，**但是**暴露了新问题」 | 每卷加 `solves` / `exposes`，强制 `volume[i].exposes == volume[i+1].solves` |
| 防重复 | 靠 ladders 的阶数 | 每 80~120 章**作废上一档的最优解** | 但是链是唯一的结构性保障 |
| 代价 | `ladders` 有 by/check/reached，**没有 cost** | 每次升级付一笔可查的损失（四路再无民田、税基只剩四川荆湖） | ladder 每级加 `cost`，无代价的升级判不合格 |

### 层 3 · 细纲 ★ 有实测

拿两本原作各 8 章真章倒推细纲，统计字段填充率：

| 字段 | 填充率 | 均长 | 结论 |
|---|---|---|---|
| 视角 / 承接 / 后果 / 账目 / 解说 / 重场 / 章末 | **100%** | 51~136 字 | 每章必填 |
| 动作 | 94% | 35 字 | 每章必填（主角不出场的章除外） |
| **误读** | **81%** | 108 字 | **事件级必填，章级选填** |
| **代价** | **50%** | 31 字 | **事件级必填，章级选填** |

两条修正：
1. **「代价」不是章级字段。** 一个五章的事件付一次代价，其余四章不付。我原本设成每章必填是错的。
2. **「解说」比我以为的重要得多。** 100% 出现且均长 130 字 —— 原作**每一章**都在讲透一条制度／数字／器物。
   这是这个调子的骨头，不是点缀。

现有细纲字段是 `一句话/承接/出场角色/剧情1-6/重场/爽点/章末钩子`，
缺 **视角 / 误读 / 后果 / 账目 / 代价 / 解说** —— 正好是「发生」和「状态」。

### 层 4 · 文风与正文提示词 ★ 有实测

A/B 四组各 3 轮（glm-5.3-flash，同一份细纲输入）：

| 指标 | A 数值目标 | B 结构指令 | C v2 | D v3 | 原作 |
|---|---|---|---|---|---|
| 字数 | 1975 | 2728 | 2859 | 2309 | 2500 |
| 对白占比 | 0.23 | 0.20 | 0.23 | 0.18 | 0.24 |
| 每千字问号 | 6.60 | 5.19 | 6.63 | **5.69** | 5.30 |
| 每千字叹号 | 8.20 | **0.14** | 7.72 | 5.64 | 8.90 |
| 段均字数 | 50.2 | 43.2 | 39.5 | **59.5** | 53.0 |
| 独立反问句 | 0.7 | 2.3 | 2.0 | **1.7** | 1.7 |
| 反讽旁白 | 0.3 | 5.3 | 6.7 | **1.0** | 2.0 |
| 误读推断 | 0.0 | 2.7 | 2.0 | 2.3 | 0.6 |
| 解说体 | 0.7 | 3.3 | 2.0 | 3.0 | 1.6 |

结构指令的写法模板（五件缺一不可）：

```
▍<要什么>
　<在什么时机做>：每当……的时候
　<怎么做>：另起一段 / 三步写法 / 用这几个起手句
　<起手句式或例子>：三到五个，具体到可以照着填
　<上下界>：三到四次，不要更多——多了会……
　<反例>：不许写成「两人商议了一番」这种概括
```

少了「起手句式」模型不知道长什么样；少了「上界」它会超调；少了「反例」它会用最省事的方式糊弄。

**未解决的问题**：v3 修好了段均和反讽，但叹号和对白又掉了 —— **约束之间在抢配额**。
出路不是继续加条目，而是**窗口级软反馈**：每 10 章量一次，把漂移的那两项回喂给下一章的提示词。

### 层 5 · 章标题

| | 现在 | 原作（2833 章统计） |
|---|---|---|
| 形态 | 意象式偏正结构（「头七夜的第一声雷」） | 台词／反问／喊话占 42%~69% |
| 点谁的名 | 主角 | **对手是主角的 1.6~2.8 倍** |
| 长度 | 不定 | 均 8.3 字，7~12 字占 64% |
| 同题连章 | 无 | 21 个块，最长**连续 25 章同一标题** |
| 形制演进 | 无 | 前半程街头喊话 → 后半程章回体对偶 |

八类功能：直呼对手 5.4%／军事术语+数字 3.2%／不要脸自嘲 3.0%／输家在喊 3.0%／
现代梗移植 2.5%／角色的错误判断 2.4%／剧透式 2.2%／阵营好X 0.6%，其余是反常识陈述句。

### 层 6 · 支线

| | 现在 | 原作 |
|---|---|---|
| 数据结构 | `threads.json`：beats 按章号钉死 + `cadence: 12/15/20` | 人 + 牌 + 牌什么时候值钱 |
| 推进方式 | 日历（每 12 章推一次） | 局势（牌价一涨他自己冒出来） |
| 分布形状 | 均匀 | 大簇 + 长空白（空白可达 1047 章） |
| 断线处理 | 「断线角色必须回归」 | 牌不值钱就该继续消失，不要"交代一句近况" |

换成 `cards.json`：`who / card / wants / fears / valuable_when / worthless_when / leverage`。
每回合问一句：**现在谁手上的牌变值钱了？**

`packs/common/cards-exemplar.json` 里有 24 张从原作抠出来的真牌 + 8 条规律
（最耐用的是双向把柄；有污点的人是最好的执行者；敌营里的明白人；自卑比野心更驱动人；
主角自造的牌可批量发；新地图＝一批新牌）。

### 层 7 · 验收

第一版闸门把**全书平均**当成**每章硬指标**，拿原作去过 —— **60 章 0 通过**。
单章方差极大（对白占比 2 分位 0.04、98 分位 0.54）。

改成两级后：

```
单章闸（只拦硬伤）      字数 / 段均 35~80 / 单段≤280 / 对白>0.02 / 结尾完整
                        → 原作通过率 86%~95%
窗口闸（每 10 章滚动）  对白 0.16~0.34 / 问 3.4~7.7 / 叹 6.6~11.3 / 段均 47~62
                        独立反问≥7 / 反讽≥12 / 误读≥2 / 解说≥8
                        → 原作通过率 65%
```

窗口闸不该硬退回（8 项同卡 5/95 分位，理论上限就是 43%），应该当**软信号回喂下一章提示词**。

另外：**误读无法用词表可靠检测。** 生成的正文明明有完整的误读三步，用词却是
「老宦是这么算的：皇帝不疯……定向清算！」，一个误读词都没命中。
**误读要从细纲层结构化校验，不要从正文层用正则数。**

### 层 8 · 模型

| 模型 | 每步耗时 | 表现 |
|---|---|---|
| `glm-5.3-flash` | 30~90s | 全链路一轮约 12 分钟。需要 `reasoning_effort: low`，否则额度全烧在思考里、可见输出为 0 |
| `deepseek-v4-flash` | 种子 288s，其余 30~180s | 慢，但**结构质量明显更高**。种子那一步值得用它 |
| `qwen3.8-flash`（项目当前默认） | **单次调用 >280s 超时** | 在 gw4 聚合网关上不可用 |

**建议按步选模型**：种子、反直觉动作、误读扩散用贵的；切章、细纲、正文用快的。

## 四、一句话

> 种子不是提纲，是发动机的八个进油口。
> 发散不是想出更多情节，是老实结算每个人会怎么误会主角。
> 支线不是待办清单，是一群手里攥着牌的人。
> 提示词的任务不是让模型**规划**，是逼它**算账**。
> 而所有关于"文风"的判断，都必须先过一遍真数据 —— 我自己就错了两条。
