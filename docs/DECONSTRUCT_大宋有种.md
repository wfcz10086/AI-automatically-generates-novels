# 拆《大宋有种》，反推生产线

读的是本地 `大宋有種.txt`（gb18030，2,173,586 字）。正文 555 章约 167 万字，之后接约 49 万字番外（用赵桓视角重写开局前八章）。均章 3889 字、中位 3148 字。

本文分四段：**这本书由什么零件构成 → 从正文倒推到种子 → 现有框架为什么写不出这种东西 → 怎么改**。

---

## 一、零件拆分

### 1.1 骨料层（开书前一次性定死，全书不动）

| 零件 | 这本书的取值 | 作用 |
|---|---|---|
| **不可改的时钟** | 宣和七年冬金兵渡黄河 → 一年内二帝北狩 | 独立于主角运行的倒计时。主角每个动作都在跟它赛跑 |
| **必死的壳** | 郓王赵楷：真实存在、真实输掉储位、真实被掳五国城 | 读者第一章就知道「他不动就得死」，不用铺垫 |
| **预装的情绪负债** | 靖康之耻、岳飞冤死、赵构南逃、秦桧 | 免费的情绪本金，作者随时提款不用先存 |
| **现成的人手清单** | 岳飞、韩世忠、宗泽、李纲、种师道、秦桧、赵构、郭药师、完颜宗翰、耶律大石…… | **这本书不造人，它派活**。读者预先认识每一个名字 |
| **一句反直觉纲领** | 「父皇别跑，儿臣有种」 | 全书种子。历史上赵楷输了储位就认命，这本书的赵楷**逼父皇别退位**，自己跑去前线 |

这五行就是整本书的发散源。注意第五行：它不是人设，是**一个把该角色的常规反应反过来的动作**。

### 1.2 引擎层（每章都在跑，这才是「发生」的来源）

四台引擎互相咬合，缺一台书就塌成传统爽文。

#### 引擎 A：误读引擎 —— 最核心，投入产出比最高

> 主角做一个动作 → 每个旁观者用**自己的处境和知识**去解释 → 解释出来的版本比主角本意大得多 → 那个错误版本变成新的现实 → 主角被迫接住。

书里的实例，全部出现在前 22 章：

| 主角真实意图 | 谁在读 | 他凭什么这么读 | 读成了什么 | 生出什么新局面 |
|---|---|---|---|---|
| 带兵入宫，不让爹跑 | 何灌、两府宰执 | 大宋没有亲王带兵闯东华门的先例 | 玄武门之变 | 主角被硬推到夺嫡位置，满朝改口 |
| 把妹妹柔福带走避难 | 崇政殿朝堂 | 金兵压境，正在议和 | 要拿帝姬去和亲 | 四位宰执联名发难，成为弹劾突破口 |
| 太困了，在陈桥驿睡一觉 | 童贯、赵佶、自己的部下 | 陈桥驿=太祖黄袍加身处 | 他要称帝 | 朝廷不敢再弹劾；部下真去找黄袍；主角被吼醒后被迫表态 |
| 说「孤带兵去河北向金人求饶」 | 金人、宋臣 | 没人信亲王会去送死 | 宋朝出了个疯子 | 「疯王」人设成立，此后所有人预期他会做出格的事 |

文本层的指纹（全书 551 章统计）：
- **独立成段的反问句：4.5 次/章** —— 「这是怎么回事？」「他想干什么？」，然后叙述给出那个人的（错误）推断
- **「以为 / 难道 / 多半是 / 看这意思」：1.2 次/章**

误读是免费的情节发生器：**一个动作 × N 个误读者 = N 条新支线**，作者不用额外设计。

#### 引擎 B：算盘引擎 —— 没有反派，只有各算各的账

书里没有一个「阻挡者」是固定的。每个人的账目都摊开写给读者看：

- 赵佶算的是「怎么跑掉且不担责任」→ 所以他既反对儿子也纵容儿子
- 赵桓算的是「怎么让爹背锅」→ 所以他既是对手也是可利用的工具
- 何灌算的是「今天在东华门砍了人，明天新官家弄死我」→ 所以他带兵来却不披甲、不带长兵器
- 秦桧算的是「投哪边活得久」→ 所以奸臣干着最积极的活

结果是**角色的功能随局势翻转**：赵佶同时是资源和阻碍；秦桧同时是隐患和干将；赵桓从第 118 章的敌人变成第 554 章被搀扶着回开封的疯老头。

#### 引擎 C：六本硬账 —— 可数、只进不退、每级付代价

全书从头到尾有六个数字化的国家状态，每章动其中一两格：

| 账 | 第 1 章 | 第 22 章 | 第 87 章 | 第 209 章 | 第 316 章 | 第 534 章 |
|---|---|---|---|---|---|---|
| 兵 | 0 | 2400 | 8000 | 36 万府兵 | 马步炮三军 | 远洋舰队 |
| 地 | 郓王府 | 陈桥驿 | 相州 | 洛阳+四川荆湖 | 河西/安西 | 东洲 |
| 名分 | 亲王 | — | 河北兵马元帅 | 官家·洪武元年 | — | 太上皇 |
| 钱 | 内藏 30 万贯 | — | 转运司春税 | 布票（纸币） | 蜀锦兑付信用 | — |
| 技术 | 连环甲 | 神臂弩 | — | — | 火鍋（曲射炮）→ 燧发 | 宝船 |
| 制度 | 皇城司 | 陈桥驿改编（军议制） | 图上谈兵+五条军议规矩 | 营田府兵+永业田 | 节度使+三军都统制 | 儒门大会/天理 |

**关键在代价，不在增长。** 每一级都写成一笔可查的损失：
- 分田养府兵 → 陕西河东京西河北四路**再无民田**，朝廷税基只剩四川荆湖（第 209 章原文明算）
- 换来 36 万府兵 → 同时得罪十万户地主，得先派十六员大将出洛阳弹压（第 211 章）
- 拿下河西 → 只能行节度使制 → **明知这是封建，会长出藩镇**（第 316 章，宰相当面点破，皇帝认了）

没有代价账，升级就没有重量。

#### 引擎 D：概念升级 —— 每 80~120 章作废一次旧的最优解

这是「不传统」的全部来源。书自己长出新问题：

```
1–130   活命      别去五国城              → 活下来了，但你没名分
130–210 立国      披麻戴孝登基、洪武改元    → 有名分了，但没钱没地
210–300 制度      营田土改、布票、府兵      → 有钱有兵了，但得罪整个士大夫阶级
300–400 技术      火鍋→燧发→棱堡           → 能碾压了，但天下三分打不动
400–480 文明      殖民 vs 封建、师宋长技     → 打出去了，但没有意识形态撑不住
480–520 意识形态  儒门大会、给儒家造一个「天」 → 有天理了，但儿子们要争
520–555 世界      大航海、罗马、东洲、八国联军 → 完
```

**每一档都让上一档的解法失效。** 第 316 章的原话就是这本书的自我意识：「南宋那边都开殖民主义了，赵楷这个穿越客统治的北宋，却还在那里搞封建」。

### 1.3 章层构造

统计（551 章）：均 3889 字 / 56 段 / 段均 49 字 / 对白占 22% / 每章 1 个场景分隔（即 2 场）/ 每千字 5.3 个问号、9.5 个叹号 / 解说体 1.8 次/章。

标准五段式（从第 1、4、20、21、86、126、209、211、316、444 章归纳）：

| 段 | 内容 | 例（第 20 章） |
|---|---|---|
| **A 外部视角开场** | **不从主角开始**，从别人怎么看主角开始 | 崇政殿君臣松了口气，因为疯王终于走了 |
| **B 信息落地** | 一个具体制度/数字/器物讲透（解说体） | 陈桥驿是太祖黄袍加身处；驿站已发展成顶得上州城的商镇 |
| **C 主角出手** | 一个动作 + 一句反常识口语台词 | 「孤欲效仿李世民」「诸君是来给孤黄袍加身的吗？」 |
| **D 后果外溢** | 立刻切走，看别人怎么被打乱 / 开始误读 | 童贯匆匆进殿：「郓王的军队在陈桥驿扎营了」 |
| **E 钩子** | 一条新消息 / 一个反问 / 一个新人名 | 同上，直接断章 |

**章标题是钩子，不是概括。** 555 个标题绝大多数是台词或喊话：
「我没疯，我要带兵入宫」「父皇，不许逃跑！」「爸爸，救命啊！」「你过河、我拆桥」「快醒醒，黄袍加身啦」「金贼，可把你们盼来了！」「宋军是来野餐的？」

对照现在框架生成的：「第1章 头七夜的第一声雷」「第2章 说不通的洞」—— 意象式偏正结构，目录页上没有一个字在勾人。

### 1.4 节奏层

- **大事件跨章打包**：第 126–131 章连着六章都叫「赵佶之死一/二/三/……」，中间不插任何别的线。第 553–554「回来了，又回来了！上/下」。
- **番外 = 同一段剧情的第二个视角**：正文完结后用赵桓视角重写第 9 章往后。作者把多视角当资产，不当装饰。

## 二、反推链条

把上面的东西倒过来，从正文往回推每一层该长什么样。

### 正文 ← 细纲

要能生成 §1.3 的章构造，细纲必须写明八件事：

```
章号 / 标题（一句台词或反问）
视角      ：本章由谁在看（优先非主角）
动作      ：主角做的那一个动作，动词开头，一句话
误读      ：谁 + 他凭什么这么想 + 读成了什么 + 他因此干了什么   ← 现在缺
后果      ：这个误读生出的新麻烦（= 下一章的输入）              ← 现在缺
账目      ：动了哪一格，from → to                             ← 现在缺
代价      ：谁受损，损了多少，能不能恢复                       ← 现在缺
重场 / 章末新信息
```

现在的细纲字段是：`一句话 / 承接 / 出场角色 / 剧情1–6 / 重场 / 爽点 / 章末钩子`。
缺的正好是**误读、后果、账目、代价**四项 —— 也正好是「发生」和「状态」这两件事。

### 细纲 ← 卷内概要

卷内概要不该是事件列表，该是六项：

1. 期初状态向量（六本账的实值）
2. 期末状态向量
3. **本卷要作废的上一卷最优解**
4. 本卷的时钟刻度（外部世界这段时间自己会发生什么，与主角无关）
5. 本卷的持续误读源：谁在这一卷里一直误解主角，误解成什么
6. 本卷付出的代价账

### 卷内概要 ← 卷要

**卷要 = 一条「但是链」**，每卷两个字段：

```
solves  ：这一卷解决什么
exposes ：解决之后新长出什么问题
```

硬约束：`volume[i].exposes == volume[i+1].solves`。

这一条约束加上去，「主角越来越强」的传统结构就物理上写不出来了 —— 因为每卷必须先把上一卷的解法作废。《大宋有种》的整条链见 §1.2 引擎 D。

### 卷要 ← 种子发散源

种子不是「人设 + 金手指」，是**三个约束撞在一起**：

```yaml
时钟:     宣和七年冬金兵渡黄河，一年内二帝北狩      # 有明确日期、读者已知、与主角无关
壳:       郓王赵楷，输掉储位，史上被掳五国城         # 真实存在、下场很惨、读者知道
反直觉动作: 不夺位，反而逼父皇继续当皇帝，自己去前线  # 把这个身份的常规反应反过来
预装情绪:  靖康之耻 / 岳飞 / 秦桧 / 赵构           # 免费情绪本金
第一句台词: 父皇别跑，儿臣有种                     # 全书的名字就是它
```

对照现在 `project.json` 的 `fields`：`premise / background / relationships` —— 写的是人设 + 金手指 + 三条感情线。**没有时钟、没有反直觉动作、没有预装情绪**。从这样的种子发散，出来的必然是「主角很强 → 越来越强」。

## 三、现有框架的诊断

用户的四句话：剧情不连续 / 状态没对上 / 很传统 / 没有发生思维。逐条落到代码和数据上。

### 病 1（不连续）细纲是预排的槽位，不是上一章的后果

`projects/大宋奸商西门庆/state.json` 的 log：

```
[22:59:14] 细纲 1-35 收 35 章
[23:09:09] 细纲 36-75 收 40 章
...
[00:59:46] 细纲 342-346 收 5 章
```

**346 章细纲在两小时内全部生成完毕，而正文只写了 6 章。** 后一批细纲的输入是前一批细纲，永远不可能是正文 —— 因为生成时正文还不存在。

正文一偏离，后面 340 章细纲全部失效，而系统不知道。这就是不连续的根。

### 病 2（状态对不上）状态是事后抽取的禁令，不是事前推导的输入

`build_context`（orchestrator.py:1583）往提示词里塞了 20 多个约束块，几乎全是否定式：
「不得推翻」「绝对禁止」「不得改口」「只进不退」「不得凭空改变」「必须与此衔接」「不得再提」……

**禁令能防倒退，不能产生推进。** 模型拿到的是一张「别踩雷」清单，不是「世界现在处于什么状态，所以接下来会发生什么」。

活的反例，同一个项目里三份骨架文件互相打架：

| 文件 | 关于何九叔说了什么 |
|---|---|
| `chapter_outlines.json` 第2章 | 「何九叔验尸，发现武大郎体内有异常硬物（弹头嵌入骨缝）」 —— **枪是第 1 章才第一次开，还打在青石板上** |
| `chapters/002.md` 实际正文 | 弹头是从**青石板缝里**抠出来的；武大郎是**中毒**死的。正文自己把逻辑修好了 |
| `threads.json` 线索1 beats | 仍写着「第2章：何九叔验出武大郎身上『找不出刀伤箭伤的洞』」，并据此排了第 22 / 115 / 220 章三个节拍 |
| `volumes.json` 第2卷 卷末钩子 | 「第60章，何九叔的尸体在运河里被捞上来」 |
| `threads.json` 线索1 ending | 「第220章：何九叔当着武松和西门庆的面说出验尸真相」 —— **一个第 60 章死掉的人** |

正文修好了，骨架没跟着改；两份骨架之间也没人对过账。第 220 章的关键戏建在一个既没发生、当事人也已经死了的事实上。

### 病 3（传统）骨架是节拍器，不是因果链

- `threads.json` 每条线有 `cadence: 12 / 15 / 20`，beats 按章号钉死 → 线索按**日历**推进，不按事件推进
- `ladders.json` 的 `by`（计划达成章）vs `reached`（实际章）：`by 15→reached 50`、`by 60→90`、`by 100→160`、`by 200→270`。差 35~70 章，系统只记录偏差，**不反过来重排**
- `stages.json` 每段钉死 `roles: {giver, blocker, rival, traitor, cost, witness}` → 谁是阻挡者从第一章就定死

固定分工 + 固定节拍 = 三幕结构走完。这就是「传统」的定义。原书里没有一个固定的阻挡者（§1.2 引擎 B）。

### 病 4（没有发生）缺「外部世界自转」这一层

框架里所有东西都挂在主角身上：power ladder、pleasure ladder、threads（全是主角关系）、stages（主角目标）。`orgs` 只是一个「势力现状」字典，被当禁令注入。

原书里金国有自己的国内政治（吴乞买 vs 宗翰 vs 完颜亮，「父慈子孝大金国」「完颜宗构最会党争」），赵构在金陵一口气取四百武进士，西夏、耶律大石、日本、罗马各有各的进度条。**这些势力在主角不在场时也在推进**，主角回头一看世界变了 —— 这是「发生」的一大半来源。

### 病 5（没有发生）完全没有误读层

框架有「爽点」「重场」「章末钩子」，没有任何字段描述「别人怎么理解主角的动作」。全文检索 orchestrator.py，`误读/误解/视角` 只出现在「开篇别雷同，换个视角切入」这种排重规则里。

**所有信息在框架里都是透明的**：模型知道真相，角色也知道真相。真相透明就只剩「谁力气大」，那就是传统爽文。

### 病 6（传统）代价没有账

`ladders` 每级有 `stage / by / check / reached`，**没有 `cost`**。`stages.roles.cost` 只是一串人名（「潘金莲」「武松（心理动摇）」），不是可查的损失。

### 病 7 章标题不是钩子

见 §1.3 末尾。这是纯提示词问题，最好改。

### 病 8 正文会截断，而且被标成完成

`chapters/003.md` 只有 1473 字节（同批其他章约 9000），断在句子中间：「一个能挑两百斤担子走山路的人，七」。而 `state.json` 的 `done` 里 3 赫然在列。这属于 memory 里那条「静默故障必须真读产出」的老毛病 —— 光看统计发现不了。

## 四、改造方案

按投入产出比排序。前三条是主刀，后面是修边。

### 改动 1 ★★★ 细纲改成滚动生成，永远只领先正文 8–12 章

把「开写前一次性排完 346 章」改成「写到第 N 章时，细纲只排到 N+10」。每次续排的输入必须包含：

- 卷要（不变的但是链）
- **当前状态向量的实值**（从已写正文抽取，不是从计划抽取）
- **最近 3 章正文原文**（不是摘要，不是计划）
- 所有活跃的误读
- 外部势力自转的结果

代码位置：`Novelist.outline_batch(want)`（orchestrator.py:3586）已经是分批的，把批次起点改成受 `state["current"]` 约束、并强制读入 `chapters/` 实际正文即可。`run_novel.py` 的阶段顺序要跟着改成「细纲 ⇄ 正文」交替，而不是「细纲全排完 → 正文」。

这一条单独做完，病 1 和病 2 的一大半就没了。

```yaml
clock:        # 必填。与主角无关、有明确日期、读者已知的倒计时
  event: 金兵渡黄河 → 二帝北狩

  who:  郓王赵楷

counter_move: # 必填。把这个身份的常规反应反过来的那一个动作
  "不夺位，反而逼父皇继续当皇帝，自己去前线"
prepaid_emotion:  # 读者不用铺垫就有感情的东西
  [靖康之耻, 岳飞, 秦桧, 赵构]

  "父皇别跑，儿臣有种"
```
